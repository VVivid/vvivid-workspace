# AgentNewsfeed

A private reading shelf and To-do checklist with fourteen built-in MCP tools. News includes the feed, Markdown reader, Archive and recoverable Trash. The [To-do contract](docs/TODO.md) shares task titles, tags, estimates, completion history and the latest Undo between the browser and MCP. News titles, introductions, links and optional thumbnails stay attributed to the original source. One Go service embeds the frontend and serves the browser, authenticated API, direct Keycloak OIDC authentication and MCP. SQLite stores private ownership, articles, checklist tasks, thumbnails, archive and Trash state, encrypted sessions and retry results.

Saved Jobs & Internships listings and retry records remain in SQLite under the [original migration](internal/store/sqlite/migrations/0004_opportunities.sql). The retired `/jobs` and `/api/v1/opportunities` routes return HTTP 404, and the MCP adapter serves only News and To-do tools.

The earlier summary-only version was deployed privately at https://newsfeed.vvivid.dev on October 27, 2026, with one explicitly verified owner and nine sourced introductory article cards. Live HTTPS readiness, sign-in routing, anonymous-access denial and SSH/shopping resource isolation checks passed. The website client is enabled; the ChatGPT client remains disabled until its actual callback and user consent are completed. Authenticated article rendering still awaits the owner’s manual sign-in. Six cards use source thumbnails through the approved exact hosts `arxiv.org`, `blog.postman.com`, `cdn.prod.website-files.com`, `engineering.fb.com` and `www-cdn.anthropic.com`; three retain placeholders. All five unique images passed the production proxy and JPEG decoding checks. Authenticated thumbnail rendering still needs browser acceptance. Local protocol tests are synthetic and do not substitute for that remaining browser/client acceptance. The reader/archive source changes described below have not been deployed; existing live content remains summary-only until its original Markdown is explicitly supplied.

## Build and run

Use Go **1.26.9**, Node.js **24**, npm **11**, and Make. The separate Go module retains its existing dependency pins. React, TypeScript, Vite and Tailwind build the frontend; real shadcn/ui Button and Separator components use Radix primitives, CVA and the standard `cn` helper. Component provenance and the local design system are documented in [web/README.md](web/README.md), with [components.json](components.json) for shadcn tooling. Identity/session and SQLite migration infrastructure is adapted into this independent project from AgentShoppingList. It imports no shopping package and changes no shopping or gateway runtime.

```sh
cd AgentNewsfeed
npm ci --ignore-scripts
make check race build
./bin/newsfeed
```

`make` builds frontend assets before compiling or testing Go. Vite writes ignored `internal/web/static/assets/app.js` and `app.css`; the Go binary embeds them and serves them under `/static/assets/`. A direct `go test` or `go build` after frontend edits needs `make frontend-build` first. Application Go checks target `./cmd/... ./internal/...` so third-party Go examples inside `node_modules` are excluded. Node is a build dependency and is absent from the runtime image.

The default listener is `127.0.0.1:8091`. With identity entirely absent the app serves a 503 setup shell, `/health/live` returns 200, `/health/ready` returns 503, and private/auth/MCP paths return 503. No account or article is seeded. A partial identity bundle or failed discovery prevents startup. `newsfeed version` reports the build version; `make build VERSION=...` sets it. SIGINT/SIGTERM allows ten seconds for graceful shutdown.

`newsfeed healthcheck live` and `newsfeed healthcheck ready` exit zero only for the matching HTTP 200 response. These commands contact only loopback at the configured listener port, use a two-second deadline, ignore ambient proxies, refuse redirects and never load identity credentials or open SQLite. Bind to loopback or all interfaces when using the built-in probe. Readiness means configured identity plus working persistence/current migrations; an unconfigured but live process intentionally fails the readiness probe.

| Setting | Value |
| --- | --- |
| `NEWSFEED_HTTP_ADDR` | Default `127.0.0.1:8091`; IP, `localhost`, or empty host plus port 1–65535 |
| `NEWSFEED_DB_PATH` | Default `data/newsfeed.sqlite`; private persistent file, never memory-only |
| `NEWSFEED_THUMBNAIL_HOSTS` | Empty by default permits public HTTPS image hosts. A nonempty comma-separated list restricts card and Markdown images to at most 16 exact lowercase DNS names, e.g. `images.example.com`; no wildcards, suffix matching or ports. DNS/IP safety checks always apply |

The process reads environment variables directly, never `.env` files. The database uses private file permissions, WAL, per-connection foreign keys, one immediate-transaction writer, a bounded read pool and two-second busy handling. Versioned migrations reject changed/newer/gapped history and unidentified databases. Readiness checks configured identity plus available persistence and complete migration history; it does not contact Keycloak on every probe. Liveness means the HTTP server is responding. Keep the database, WAL and session keys persistent across restarts and outside source control.

## Local container packaging

[Dockerfile](Dockerfile) uses the same pinned Go 1.26.9 build image and distroless Debian 13 runtime digests as the shopping project. A digest-pinned Node 24 stage builds the frontend; both Go binaries and the embedded UI are built from source; no host binary, data, development record, secret or tool cache is in the allowlisted build context. The image runs as UID/GID **65532**, with `/data` owned by that user and mode **0700**. Its built-in Docker healthcheck runs `/newsfeed healthcheck ready`. No shell or curl is required in the runtime.

```sh
make compose-check container-build container-test
docker image inspect --format '{{.Id}}' agentnewsfeed:local
```

`container-build` downloads the pinned base images, locked npm packages and declared Go modules, verifies npm integrity and module checksums, and writes the resulting local image ID under the ignored task directory. `TEST_IMAGE` defaults to `agentnewsfeed:local`; tests resolve it to its immutable local image ID before running. Nothing is pushed. A local image ID is content-addressed evidence about that image, not a registry publication digest.

Standard `HTTP_PROXY`, `HTTPS_PROXY` and `NO_PROXY` build arguments are forwarded without embedding their values in the image. In an environment requiring a private build-network CA, `make container-build BUILD_CA_FILE=/path/to/public-ca-bundle.pem` mounts that public certificate bundle through BuildKit only for verified npm/module downloads. The Node stage uses `NODE_EXTRA_CA_CERTS` with that secret; the Go stage uses `SSL_CERT_FILE`. It never copies the bundle into the runtime image or disables TLS/Go checksum verification. No CA override is needed on an ordinary trusted build network.

`container-test` uses synthetic enrollment/article/retry fixtures in a throwaway dedicated volume. It runs the real production executable as UID65532 with a read-only root, no capabilities, no privilege escalation, no published ports and `--network none`; checks fail-closed unconfigured health/private routes, proves writes outside `/data` fail, and verifies embedded frontend assets and SQLite/original-Markdown/archive/retry persistence, plus To-do tasks, completion timestamps, latest Undo and historical mutation snapshots, across process restarts and actual container stop/start. Docker's readiness healthcheck must mark the deliberately unconfigured container unhealthy. All test containers and their volume are removed; the image and ignored test evidence remain. This test does not configure or claim a live identity integration.

[deploy/compose.yaml](deploy/compose.yaml) is prepared for the existing HTTPS Traefik network. It publishes **no backend host port**, runs one instance with a read-only root, drops capabilities, disallows privilege escalation, and mounts a dedicated named SQLite volume. Its required variables have no production defaults; [deploy/environment.example](deploy/environment.example) contains only placeholders. `compose-check` resolves a synthetic configuration and rejects missing required inputs without loading an operator `.env` or reading secret contents. CI performs the same local packaging checks.

For separately authorized activation, select a verified release image **with registry digest**, dedicated volume name, exact origin/issuer/client/audiences, exact existing Traefik network/HTTPS entrypoint/certificate resolver, and two private host file paths. Local Compose bind-mounts file secrets using the source files' ownership/modes; it does not remap their UID or fix permissions. Prepare secret files owned/readable by UID65532 with exactly **0400 or 0600** before use, keep them outside this checkout and the SQLite volume, and mount them read-only through Compose secrets. A fresh named volume receives the image's private `/data` ownership; an existing volume must already have the correct UID and mode. The operator can validate their private environment file with `docker compose --env-file "$newsfeed_private_environment_file" -f deploy/compose.yaml config --quiet`. ## Exact identity configuration

All eight settings below are required together. The origin is an operator-selected HTTPS origin with no path or trailing slash. The examples are placeholders; they are not a selected live hostname or realm. Secret values belong in private runtime files outside this source tree and must never be printed in logs or chat.

| Setting | Required contract |
| --- | --- |
| `NEWSFEED_ORIGIN` | Exact HTTPS origin, e.g. `https://newsfeed.example.com` |
| `NEWSFEED_OIDC_ISSUER` | Exact verified Keycloak issuer, e.g. `https://identity.example.com/realms/personal` |
| `NEWSFEED_WEB_CLIENT_ID` | Dedicated confidential browser client, e.g. `newsfeed-web` |
| `NEWSFEED_WEB_CLIENT_SECRET_FILE` | Private regular file containing that client's generated secret |
| `NEWSFEED_API_AUDIENCE` | Exactly `$NEWSFEED_ORIGIN/api/v1` |
| `NEWSFEED_MCP_AUDIENCE` | Direct mode: exactly `$NEWSFEED_ORIGIN/mcp`; gateway mode: `agent-newsfeed-mcp` |
| `NEWSFEED_MCP_CLIENT_IDS` | Exact allowlist of dedicated registered MCP clients, initially `newsfeed-chatgpt` |
| `NEWSFEED_SESSION_KEYS_FILE` | Private JSON keyring containing an active key and one to three named AES-256 keys |

Secret files must be regular, at most 16 KiB and mode 0400 or 0600. The session keyring shape is `{"active":"k1","keys":{"k1":"BASE64_OF_32_RANDOM_BYTES"}}`; this placeholder is not a key. Generate real random keys privately through the operator's secret workflow and keep them stable across ordinary restarts. Rotate by adding a new active key while retaining old decrypt-only keys for at least 12 hours 10 minutes, then restart; refreshed sessions reseal under the active key. Removing an old key early signs out its sessions. No new key/plaintext fallback exists.

The following direct-mode instructions apply to standalone deployment. For the R&D gateway deployment, follow [production setup](deploy/gitops/README.md) and its linked homelab resources. Configure Keycloak directly, without importing or replacing an existing realm:

1. Register the browser client as confidential, standard authorization-code flow only, PKCE **S256**, exact redirect `$NEWSFEED_ORIGIN/auth/callback`, exact post-logout redirect `$NEWSFEED_ORIGIN/`, exact web origin, and `client_secret_basic` token authentication. Disable implicit, password, service-account, wildcard redirect and dynamic-registration paths. Register each MCP client's exact callback verified from the actual client; do not guess it or copy the shopping callback blindly.
2. Define `newsfeed:read` and `newsfeed:articles:write`. The browser requests `openid newsfeed:read newsfeed:articles:write`, and receives only the API audience. Manual archive/restore requires an explicitly issued write scope; read permission never implies it. MCP grants receive only their selected newsfeed permissions and the MCP audience. Remove unrelated inherited audiences/scopes. Offline/background grants are not supported. Standard `openid`, `profile`, `email` identity scopes may accompany tokens; no unrelated permission scopes may accompany a newsfeed token.
3. Use an exact resource audience mapper per client and emit `sub` from the authenticated user's subject (`oidc-sub-mapper`, `access.token.claim=true`). Access tokens require RS256, JOSE type `JWT` or `at+jwt`, body `typ=Bearer`, exact `iss`, nonempty `sub`, a **single** intended `aud`, registered `azp`, `iat`, `exp`, valid `nbf` when present, and lifetime at most **300 seconds**. Validate newly issued tokens after mapper changes. ID tokens never authorize MCP or the read API.
4. Verify discovery advertises S256 and authorization, token, JWKS, revocation and end-session endpoints on the exact issuer origin. The app requests the API `resource` during browser authorization, exchange and refresh. Ensure the issuer/proxy accepts this new resource independently without changing shopping/SSH enforcement.
5. Explicitly enroll the permitted issuer+subject through the offline operator command below. Signing in never creates an account. Initially enroll only the intended owner; other acceptance users belong in synthetic tests or separately authorized accounts.

```sh
./bin/newsfeed-admin enroll --db "$NEWSFEED_DB_PATH" \
  --issuer "$NEWSFEED_OIDC_ISSUER" --subject-file "$newsfeed_verified_subject_file"

./bin/newsfeed-admin disable --db "$NEWSFEED_DB_PATH" \
  --issuer "$NEWSFEED_OIDC_ISSUER" --subject-file "$newsfeed_verified_subject_file"
```

The subject file must be private, at most 256 bytes, containing the exact verified subject with at most one terminal newline. Enrollment prints only an opaque local account ID and rejects duplicates. Disable atomically blocks future owner resolution and revokes all that account's local sessions, preserving articles. No HTTP/MCP route can enroll, disable or choose an account.

After independently verifying the intended owner's issuer/subject and enrolling it, the offline operator can seed a vetted manifest without waiting for an MCP consent flow:

```sh
./bin/newsfeed-admin seed --db "$NEWSFEED_DB_PATH" \
  --issuer "$NEWSFEED_OIDC_ISSUER" --subject-file "$newsfeed_verified_subject_file" \
  --articles-file "$newsfeed_vetted_seed_manifest"
```

The manifest is one JSON array of **1–50** `add_article` inputs, at most **1 MiB**, with a distinct, stable `idempotency_key` for every request and `article: {url,title,summary,thumbnail_url?,content_markdown?}`. Unknown fields, trailing documents and invalid content are rejected. Keep the actual vetted manifest outside source/image; it is user data, never an embedded fixture. The initial seed uses text/placeholders with no image hosts. The operator command uses the same `NEWSFEED_THUMBNAIL_HOSTS` policy as the application, empty by default.

Seed resolves an **existing active** exact issuer+subject enrollment and never auto-enrolls or constructs an HTTP principal. All content/key/thumbnail validation completes before the first write, using the feed's shared pure normalization. Writes use the existing owner-checked canonical deduplication and atomic article/retry-result transactions; there are no deletes, replacements or unchecked SQL. Each request commits separately. A later storage/key conflict can leave earlier requests committed; the error reports how many completed, and retrying the **unchanged** manifest safely replays them. A changed intent needs a new key, and an existing article's introduction remains unchanged by deduplicated adds. The success message counts processed requests, not newly inserted rows. No browser or MCP capability is added by this operator command.

The browser uses authorization code + PKCE, nonce, state, optional issuer response binding, verified ID/access subject equality, and hashed host-only Secure/HttpOnly/SameSite=Lax cookies. AES-GCM session ciphertext is bound to the cookie hash, owner, client and purpose. Browser sessions persist encrypted OAuth/CSRF state, refresh at least every 60 seconds or near access expiry, and expire absolutely after 12 hours. Refresh failure revokes the local session. Logout requires POST, exact Origin and CSRF, revokes locally first, then revokes the issuer refresh grant. If provider revocation fails it returns 502 while remaining signed out locally. MCP checks active local enrollment on every request; provider revocation of existing JWTs is bounded by their accepted 300-second lifetime, without introspection or back-channel logout.

Run behind HTTPS termination preserving the canonical Host. The application checks Host and any supplied Origin against its configured origin; forwarded identity/host headers cannot authenticate or override them. Proxy request limits and timeouts must permit MCP Streamable HTTP, preserving Authorization/Accept/MCP protocol headers. Browser cookies remain Secure even with the HTTP backend listener. Loopback HTTP issuers are accepted only for local protocol tests; public HTTP issuers are rejected.

The legacy direct deployment's shared Keycloak login proxy needs the separately reviewed [newsfeed compatibility bundle](deploy/oauth-compat/README.md) before it can accept the new resources. It adds only an optional `newsfeed_origin` and fixed `newsfeed-web`/`newsfeed-chatgpt` resource bindings; no Codex binding or gateway for newsfeed tools. The deployed Keycloak resource-indicator behavior also requires canonical bearer-only URI resource registrations for the API and MCP, in addition to those interactive clients and their correct scopes/audiences. Actual ChatGPT callback/consent remains pending the new setup. Shared-proxy application/restart has its own action-time approval and independent recovery/rollback boundary; preparing the bundle performs no live change.

## MCP gateway authentication mode

`NEWSFEED_MCP_AUTH_MODE` defaults to `direct` (also when absent). In `gateway` mode set `NEWSFEED_MCP_AUDIENCE=agent-newsfeed-mcp`, `NEWSFEED_MCP_GATEWAY_ISSUER` to the exact HTTPS gateway origin (`https://mcp.rd.lab.vvivid.dev` in production), and `NEWSFEED_MCP_GATEWAY_JWKS_FILE` to an operator-installed public JWKS. These gateway settings are rejected in direct mode. The normal eight identity fields remain required. `NEWSFEED_OIDC_ISSUER` stays the original R&D issuer, browser API audience stays the browser origin plus `/api/v1`, and `NEWSFEED_MCP_CLIENT_IDS=newsfeed-chatgpt` is production's sole MCP client.

Only `/mcp` changes verifier. It accepts a compact RS256 JWS with protected `typ=mcp-gateway+jwt`, nonempty pinned `kid`, exact gateway `iss`, sole backend `aud`, original `identity_issuer` exactly equal to the configured OIDC issuer, original nonempty `sub`, allowed `client_id`, and only `newsfeed:read` / `newsfeed:articles:write` scopes. Positive `iat`, `nbf`, `exp` must be time-valid with lifetime and remaining validity at most 60 seconds (five-second future-issued tolerance, no future nbf or expiry grace). JWKS is bounded to 64KiB and one to eight distinct public RS256 signing keys, RSA at least 2048 bits; private keys, weak keys, unknown algorithms and duplicate IDs fail startup. Keys load at startup; deliberate rotation requires installing old+new public keys, restarting the backend, switching the gateway key, then retaining old trust through expiry/in-flight requests.

Ownership resolves **original `(identity_issuer, sub)`** against current local enrollment on every request. Gateway `iss`, matching subject text from another issuer, body fields and forwarded identity headers never choose an owner. MCP per-operation scopes, revision checks and durable idempotency are unchanged. Direct external tokens cannot authorize gateway-mode MCP. Browser login, encrypted sessions, API audience, direct provider validation, refresh, CSRF and logout remain unchanged; gateway JWTs cannot authorize browser/API paths.

The app suppresses direct MCP protected-resource metadata and OAuth challenges in gateway mode. The gateway owns metadata at `https://mcp.rd.lab.vvivid.dev/.well-known/oauth-protected-resource/agent-newsfeed/mcp` and externally accepts only the route URL as audience, with five-minute provider lifetime. Browser cookies keep canonical `newsfeed.vvivid.dev`; the gateway's fixed upstream sets that exact Host. Public browser ingress permits only actual browser/auth/article API/static/thumbnail paths; `/mcp`, discovery and health have no public route. No dependency on a sibling filesystem or gateway Go module is introduced; [the wire-contract verifier](internal/identity/gateway.go) implements MCPGateway v1 independently.

The legacy [OAuth proxy compatibility bundle](deploy/oauth-compat/README.md) is retained for the old direct deployment; the new R&D production setup does not require changing that proxy, its realm or old server.

## Reader and archive

Opening an article never archives it. A manual Archive or Restore form sits at the end of the article, ready when you finish reading. The reader shows the source title, introduction, attribution and original link, then the stored original Markdown in a narrow reading column. The agent must supply the **complete original source article as Markdown**, preserving its wording; do not substitute an agent-written summary or rewritten article. No page fetch, scraping, extraction or image discovery runs on the server. If the full source is unavailable, omit `content_markdown`: old and new summary-only records show the introduction and **Read original** fallback.

The reader supports headings, paragraphs, lists, quotations, links, code and source-provided Markdown images. Safe relative, protocol-relative and fragment links resolve against the original source URL. Relative and protocol-relative image destinations also resolve against the source and must produce a permitted public HTTPS URL. React escapes text and raw HTML stays disabled. External links use `noopener noreferrer`; images load only through the owner-checked proxy described below. The autumn theme uses aged paper, oxblood serif headings, faded brick actions and thin sage dividers, with a darker walnut for readable small text. Filled link buttons retain light text during hover and keyboard focus; outline, ghost and text-link variants keep their respective theme colors. Feed/archive links, forms and pagination work with normal browser navigation, refresh and deep links; sign-in preserves a validated local return destination.

Archive removes an article from the active feed while retaining its source and full content. Restore returns it to the feed at its original saved position. Active articles sort by `created_at DESC, id DESC`; archived articles sort by `archived_at DESC, id DESC`. Cursors belong to one owner and one view and must be passed back unchanged. A cursor from the old summary-only release must be replaced by starting the list again. Pagination is stable for unchanged articles; state changes between pages are reflected in subsequent reads.

Each real archive/restore state change increments `revision` and updates `updated_at`; repeating the same state is a no-op, preserving both revision and archive order. A concurrent content update must use the current revision. Content updates preserve archive state, canonical duplicates never unarchive, and durable MCP retry results retain their original outcome even after a later edit or archive operation.

**Browser grant compatibility:** earlier browser sessions granted only `newsfeed:read`. They remain usable for reading; the UI disables archive/restore and explains the missing write permission. A separately authorized identity configuration change must allow `newsfeed:articles:write` for the exact `newsfeed-web` API resource, followed by sign-out/sign-in (and consent if configured) before manual archive/restore is available. The app accepts only scopes actually signed into the grant; it never upgrades a read-only session itself. This source change does not alter live Keycloak clients, grants, proxy configuration or deployed services.

Migration `0002_reader_archive.sql` adds bounded `content_markdown` and nullable `archived_at`; all existing rows become active with an empty body. It preserves existing article values, migration history and retry-result bytes. Empty optional fields stay absent from normalized JSON so pre-reader add/update payload hashes continue to replay. Startup migrates the configured SQLite database atomically; an older binary rejects a newer schema. Back up the private database through the operator's existing process before a separately authorized production upgrade, and use that backup for a schema rollback.

## Routes and MCP contracts

| Route | Access |
| --- | --- |
| `/` | Sign-in gate or the authenticated account's active feed; newest-saved first |
| `/archive` | Sign-in gate or the authenticated archive; newest-archived first |
| `/trash` | Sign-in gate or recoverable Trash; newest-trashed first |
| `/articles/{article_id}?from=feed\|archive\|trash` | Authenticated owned reader with the matching back link; GET never changes state |
| `/api/v1/articles?limit=20&cursor=...&archived=true` | Browser session + `newsfeed:read`; default active; `archived=true` selects Archive, `trashed=true` selects Trash (mutually exclusive); limit 1–50, no bodies or image bytes |
| `/api/v1/articles/{article_id}` | Browser session + read permission; full owned article including optional Markdown; `trashed=true` is required for Trash |
| `POST /api/v1/articles/{article_id}/archive` and `.../restore` | Browser session + read **and** write permission; bounded URL-encoded form with one `csrf_token`, exact Origin; redirects to the updated reader |
| `POST /api/v1/articles/{article_id}/trash` and `.../restore-trash` | Browser read + write; CSRF/Origin-protected native form with `expected_revision` and `idempotency_key`; redirects to the corresponding reader |
| `/todo` | Sign-in gate or the owner's checklist, today's completions, and history |
| `POST /api/v1/todos` | Browser read **and** write; bounded URL-encoded form with one `csrf_token`, exact Origin, and an `action` and `task_id`. Add accepts `title`, `tags` and `estimate_minutes`. Complete, reopen, remove and undo require `expected_revision`. |
| `/thumbnails/{article_id}` | Browser session + read permission and owned article; saved JPEG bytes, or legacy protected proxy; `trashed=true` explicitly selects Trash; no URL fetch argument |
| `/thumbnails/{article_id}/content/{image_id}` | Same authorization; opaque image ID must match a Markdown image in the current persisted article, with no URL fetch argument |
| `/auth/login`, `/auth/callback`, `/auth/logout` | Direct OIDC flow; logout is a CSRF-protected POST |
| `/mcp` | Stateless official Go SDK Streamable HTTP, bearer authentication on every request; request limit 2 MiB |
| `/.well-known/oauth-protected-resource/mcp` and `.../api/v1` | Exact resource, issuer and permitted read/write scopes |
| `/health/live`, `/health/ready` | Separate liveness/readiness |

Private/auth responses use `Cache-Control: no-store`, a restrictive CSP (`script-src`, `style-src`, `connect-src` and `img-src` limited to self), and `Referrer-Policy: same-origin`. There are no inline executable scripts, unsafe-inline/eval allowances or third-party browser loads. Same-origin referrer policy lets native archive/restore/logout POST navigations retain their exact Origin for CSRF validation while withholding all cross-origin referrers. External article links additionally use `noreferrer`. The server places escaped JSON in the shell's `data-bootstrap` attribute, including the session CSRF token and actual write capability; article content remains untrusted display data.

To-do stores tasks in SQLite with migration `0005_todo_tasks.sql`; additive `0006_todo_idempotency.sql` adds durable MCP retry results and a visible-task index. Completion records a UTC timestamp. The collapsed Completed disclosure groups finished tasks by date in America/New_York. Open tasks carry forward. The most recent removal per owner remains undoable across reloads until it is undone or another task is removed. Repeating Add with the same task ID and content keeps its current state. Browser and MCP share the checklist and latest Undo. The [six To-do tools](docs/TODO.md#permissions-and-mcp-operations) use the existing read grant for reads and both read/write grants for every mutation and exact retry. Distinct add keys create distinct tasks; successful retries return historical snapshots without repeating state changes.

The MCP adapter advertises version `0.3.0` and exposes eight News tools and [six To-do tools](docs/TODO.md#permissions-and-mcp-operations).

| Tool | Input and behavior |
| --- | --- |
| `add_article` | `idempotency_key`, `article: {url,title,summary,thumbnail_url?,content_markdown?}`. Requires `newsfeed:articles:write`. Returns `{article,created}`; duplicate canonical URLs return the existing article unchanged with `created=false`. New articles enter the active feed. |
| `list_articles` | Optional `limit` 1–50, opaque `cursor`, and mutually exclusive `archived` / `trashed` booleans (default false); requires `newsfeed:read`. Returns `{articles,next_cursor?}` in the selected view's order. Lists omit `content_markdown`. Write permission does not imply read permission. |
| `update_article` | `idempotency_key`, `article_id`, `expected_revision`, and full replacement `article`; requires write permission. Revision or canonical URL collisions conflict without partial changes. **Omitting `content_markdown` clears the saved body; omitting `thumbnail_url` clears the thumbnail.** Preserve these fields when updating other content. Archive state is preserved; Trash must be restored before editing. |
| `get_article` | `article_id`, optional `trashed` (default false). Requires read permission. Returns the full owned article, including saved body and image metadata, never image bytes. Ordinary reads exclude Trash. |
| `patch_article` | `idempotency_key`, `article_id`, `expected_revision`, `patch: {url?,title?,summary?,thumbnail_url?,content_markdown?}`. Requires both `newsfeed:read` and `newsfeed:articles:write`. Omitted fields stay unchanged. Explicit `null` or empty string clears only the optional body/thumbnail; URL, title and summary cannot be cleared. Empty, unknown, duplicate or invalid patch fields are rejected. Explicit `thumbnail_url` refreshes the image even when the URL is unchanged. |
| `trash_article` | `idempotency_key`, `article_id`, `expected_revision`. Requires both `newsfeed:read` and `newsfeed:articles:write`. Moves an article to recoverable Trash, retaining content, thumbnail and its original Feed/Archive state. |
| `restore_article` | Requires both `newsfeed:read` and `newsfeed:articles:write`. Same mutation fields. Restores Trash to its original Feed or Archive state; never permanently deletes. |
| `set_article_archived` | Requires both `newsfeed:read` and `newsfeed:articles:write`. Same mutation fields plus required `archived` boolean. Explicitly selects Archive (`true`) or Feed (`false`), preserves content, and rejects Trash. Setting the current state is a successful no-op. |

Titles are 1–300 UTF-8 bytes; summaries are 1–1200 bytes of short source-backed introduction. Both reject control characters and surrounding whitespace. Optional Markdown is at most **256 KiB of UTF-8 bytes**; source whitespace is preserved and only tabs, carriage returns and line feeds are allowed control characters. The 2 MiB MCP envelope accommodates JSON escaping of a maximum-size body. The offline seed manifest retains its independent 1 MiB total limit. Keys are 1–128 bytes. Article results include `revision`, `created_at`, `updated_at` and, when archived/trashed, `archived_at` / `trashed_at` as Unix milliseconds. Stored thumbnails include `thumbnail_hash`, `thumbnail_width`, `thumbnail_height`, `thumbnail_bytes` and `thumbnail_status`; no BLOB or Base64 is included. Full detail and mutation results include nonempty `content_markdown`; list responses omit it.

The new read-modify tools (`patch_article`, `trash_article`, `restore_article` and `set_article_archived`) return the stored full article, so both scopes are checked on every call, including exact retries, before stored-content lookup or image fetching. `add_article` and `update_article` retain their existing write-only authorization and durable result contracts.

Successful MCP writes persist the exact result atomically with the article; retries with the same owner/key/operation/normalized content return that original result even after later edits or restart. Reusing a key for another intent conflicts. Failed validation/revision/collision writes reserve no key. Retry records have no automatic expiry. Retries are resolved before external image fetching and rechecked inside the write transaction. Trash is separate from Archive: Feed/Archive lists, ordinary reads, content edits and archive actions exclude it. Canonical URL deduplication includes Trash and never revives it. `get_article` and `list_articles` require explicit `trashed=true` for that view; cursors cannot cross owners or views. Restore preserves the original archive timestamp and saved time. No permanent deletion, automatic Trash expiry or full-text crawling runs.

URLs must be bounded HTTPS links with a public DNS hostname, no credentials, nondefault port, dot path segments or whitespace. Canonicalization lowercases DNS names, removes default port 443 and fragments, normalizes unreserved escapes, sorts query keys, and removes `utm_*`, `fbclid`, `gclid`, `dclid`, `msclkid`, `mc_cid`, `mc_eid`. Meaningful query values, repeated-value order, encoded slashes, trailing slashes and path case remain significant. `www` and non-`www` hosts remain distinct; no redirect/page probing infers equivalence. Source links are validated syntactically and never fetched by the server.

## Image policy

Supply `thumbnail_url` only when the source provides an image URL. Public HTTPS DNS hosts work by default without per-publisher configuration. A nonempty `NEWSFEED_THUMBNAIL_HOSTS` optionally restricts images to those exact hosts; a thumbnail outside that restriction is rejected on add/update. Omit `thumbnail_url` for the local card placeholder. Markdown images stay in the reader and do not automatically become card thumbnails. No Open Graph, favicon, screenshot, article metadata, page scraping or image discovery runs, and the server never fills in missing images.

New add/update requests with a thumbnail fetch and process it **before** opening a database write transaction. Successful retries, canonical duplicates, stale revisions and known URL collisions are checked first; the transaction rechecks retry identity, canonical uniqueness and revision after any fetch. No article pages, discovery, file-upload UI, background worker, extra PVC or startup backfill is involved.

Processed thumbnails are JPEG BLOBs on the existing SQLite/PVC. Catmull-Rom resizing preserves aspect ratio without upscaling, with a longest edge of at most **640 pixels**. JPEG quality starts at **75**, with bounded quality and dimension reductions to enforce a hard **100 KiB** payload limit. Re-encoding strips source metadata. Identical processed bytes share one SHA-256 payload **within an owner**. The **50 MiB payload budget per owner** includes Archive and Trash, counts shared bytes once, and credits an old unshared payload during replacement. Clearing/replacing a thumbnail and deleting its last unreferenced BLOB happen in the article/retry transaction. Trash retains the reference for restore. Article reads and durable retry JSON contain only metadata, never BLOB bytes or Base64.

`thumbnail_status=stored` serves the saved JPEG from the authenticated owner/article route without any repeat source request. Network/image failures still save usable article content with `unavailable`; a full budget gives `budget_exceeded`. Both use the local placeholder and no remote read fallback. To retry, use a **new key** and explicitly patch `thumbnail_url`; an exact successful retry keeps the original outcome even when source availability or storage capacity changes. Partial edits that omit the thumbnail leave its image and status unchanged. Full replacement retains an already stored image when its URL is unchanged; omitting the URL clears it.

Migration `0003_thumbnails_trash.sql` adds owner-scoped BLOB/reference tables and Trash metadata without changing earlier migrations, article content or existing durable retry bytes/hashes. Existing URL-only thumbnails are marked `legacy` and keep their previous authenticated, bounded remote proxy behavior until an explicit thumbnail update materializes a stored JPEG. Migration and browser reads never download-and-save legacy images. The offline seed command also creates URL-only legacy thumbnails; an agent can materialize each one with an explicit thumbnail patch. Back up SQLite consistently before deployment. Older binaries reject the newer migration history; recovery requires the previous image and the consistent pre-migration database backup.

Inline Markdown images retain the remote protected proxy. The reader derives an exact destination-to-local-route manifest by parsing persisted Markdown with pinned CommonMark parser Goldmark. Repeated and reference-style images work without assuming parser indexes align. Every request checks read permission, owner, selected Trash state and current saved image reference. Raw HTML, links, removed images and invented IDs cannot authorize a fetch. The browser never receives an external image `src`; unknown destinations and failures show local alt text. Trash image URLs explicitly select `?trashed=true`.

The shared fetcher sends no browser cookies, Authorization, proxy credentials or environment proxy settings. Every initial/redirect destination uses HTTPS on implicit port 443, a public DNS hostname and any configured exact-host restriction. Each connection resolves DNS, rejects the entire answer set if any address is private, loopback, link-local, multicast, reserved, mapped IPv6, tunnel/translation, documentation or metadata/platform space, then dials a pinned public IP with TLS hostname verification. Redirects are limited to two and revalidated. No query argument chooses the fetched URL.

Fetching has a five-second total deadline, two-second connection/TLS/header limits, 16 KiB headers, four concurrent fetches shared across thumbnail writes and image reads, and at most 2 MiB input. JPEG/PNG only: GIF, WebP, AVIF, SVG, compressed HTTP bodies, HTML, malformed images, dimensions under 64 on either axis, over 2048 on either axis or over 1,048,576 source pixels are rejected. Source bounds apply before decoding/resizing. Legacy thumbnails and inline figures retain the previous metadata-stripped JPEG proxy output bound of 2 MiB. An allowed image host observes server-side requests, not browser cookies or the browser's IP. Local tests use controlled servers; live image compatibility is separate.
