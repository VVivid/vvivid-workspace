# Newsfeed frontend

React and TypeScript render News and To-do. News includes the feed, archive, Trash and reader. Vite emits `internal/web/static/assets/app.js` and `app.css`; Go embeds those files and its escaped HTML shell. There is no frontend server in production. Run `npm ci --ignore-scripts`, then `make check race build`. `make frontend-check frontend-test frontend-build` runs the frontend checks alone.

The shell supplies escaped JSON in `#root`'s `data-bootstrap` attribute. It contains only the current owner's requested list or detail, the session CSRF token, actual write capability and a reader image manifest derived from that article's persisted Markdown. The browser uses the same URLs for navigation, refresh and deep links. React requests the current page data with `Accept: application/vnd.agentnewsfeed.browser+json` and updates history after it loads. Back and Forward fetch fresh page data. State forms send their existing URL-encoded fields and receive a destination to load after a successful write. Native form submissions still redirect. Modified clicks, source links and sign-in and sign-out use browser navigation. Archived articles remain readable. Trash has separate navigation and explicit reader links; native Trash/Restore forms carry the CSRF token, expected revision and idempotency key. Trash preserves the prior archive state and offers restore rather than archive controls. No permanent-delete control exists. Markdown runs through `react-markdown` with raw HTML disabled; never add a raw-HTML plugin or render article content with `dangerouslySetInnerHTML`.

News lists use Previous and Next in each view. A native shell starts with up to three rows. Browser JSON requests use `X-Newsfeed-Page-Size` to select three rows at widths of 640px or less and five at wider widths. At the breakpoint the app reloads the current list position in place. The `cursor` and `before` query values select positions within an owner's view, and the same links work across viewport sizes. Detail and back links preserve that position.

To-do bootstrap carries the signed-in owner's task list and latest undoable removal. The compose draft lives in the current SPA session and keeps its Add ID across a read refresh or manual retry. State actions use a task's current revision. After a successful write, the app refreshes the checklist in place. Failed writes are shown separately from failed refreshes, which retry only the GET. The open page regroups persisted completion timestamps using the browser clock and America/New_York at midnight, and rechecks the date on return to a backgrounded page.

Markdown images must match an exact destination in the server's `content_images` manifest. Their `src` can only be a local `/thumbnails/{article_id}/content/{image_id}` route, which rechecks browser read permission, ownership, explicit Trash selection and the current saved image reference before using the bounded HTTPS JPEG/PNG proxy. Relative destinations resolve against the original source on the server. Unknown/unsafe references, invalid manifests and proxy failures display local alt text without an external browser request. A shared fixture tests Goldmark/react-markdown destination compatibility, including reference-style, repeated, escaped and relative images. Raw-HTML images remain disabled. Feed cards require an explicit source-provided `thumbnail_url`. Stored thumbnails use saved SQLite JPEG bytes through the same owner/article route, never a browser external source or a repeat download. Legacy URL-only records keep their protected proxy until explicitly refreshed. Missing, unavailable or budget-exceeded images retain the local card placeholder. Trash thumbnail and figure routes explicitly select `?trashed=true`.

`styles.css` defines a fixed light autumn theme: paper `#E8E2D3`, surface `#F2EDE3`, oxblood `#49232D`, brick `#903F32`, ink `#302824`, walnut `#866257` and sage `#AAA68F`. Small muted text uses darker walnut `#79594F` for readable contrast. The generic anchor color belongs to Tailwind's base layer so Button variant utilities retain their intended colors on both anchors and buttons, including hover/focus. Serif headlines, broad margins, horizontal rows and thin dividers carry the editorial layout. Components have visible keyboard focus and respect reduced-motion preferences. Search and alternate sorting are deferred.

## shadcn/ui provenance

`components/ui/button.tsx` and `separator.tsx` adapt the canonical shadcn/ui new-york v4 registry components:

- [Button registry source](https://ui.shadcn.com/r/styles/new-york-v4/button.json): CVA variants, Radix Slot composition, typed props, `data-slot` and `cn` merging.
- [Separator registry source](https://ui.shadcn.com/r/styles/new-york-v4/separator.json): Radix Separator, decorative/orientation props, typed props and orientation-aware classes.

The upstream [MIT license](SHADCN-LICENSE.md) is retained and copied into the runtime image. The theme adapts spacing, variants, radius and focus treatment, removes shadows, and uses the individual `@radix-ui/react-slot` and `@radix-ui/react-separator` packages instead of the umbrella Radix package. Dependencies also include `class-variance-authority`, `clsx`, `tailwind-merge` and Tailwind CSS. `components.json` records the shadcn aliases and stylesheet. Arrow and leaf SVGs are local source, requiring no icon/font network request.

Frontend tests cover private shells, both sections and their deep links, Feed/Archive/Trash pagination and keyboard navigation, proxy-only News thumbnails and failure placeholders, original Markdown, protected Markdown images and failure alt text, raw-HTML/unsafe-link rejection, native revision/retry/CSRF forms, legacy summary fallback and missing write capability. Go integration tests exercise persisted authenticated routes, state/retry/ownership/CSRF boundaries and actual MCP SDK calls.
