Failure trace: an existing old schema needs forward migrations. Startup validates its history and attempts a verified pre-migration archive. If backup cannot complete, startup refuses before applying SQL. A corrupt/newer/drifted backup, foreign-key defect, changed hash/manifest, canceled operation, existing target/symlink or target sidecar fails recovery without publishing a new target. A later SQL migration failure can retain earlier migration commits; the verified old-schema archive remains the rollback route. There are no reverse migrations.
